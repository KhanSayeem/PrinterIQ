# Domain Docs

PrinterIQ uses a single-context domain layout.

## Before Exploring

- Read root `CONTEXT.md` when it exists.
- Read relevant architectural decisions under `docs/adr/`.
- Read `PrinterIQ_PRD_v1.0.md` as the authoritative product and architecture source when available.

Proceed without interruption when `CONTEXT.md` does not yet exist. Domain-modeling work may create it when terminology needs to be formalized.

## Vocabulary And Decisions

- Use established PrinterIQ domain terms in issue titles, plans, tests, and code.
- Do not silently introduce synonyms for defined concepts.
- Explicitly identify when proposed work conflicts with an existing ADR or the PRD.
- Add a superseding ADR before implementing an approved architectural change.
